## 1. Architecture overview

```
 +---------------------------------------------------------------------------------------------------+
 | main loop (thread)  link_poll · afe_drain → stream · cmd dispatch · events flush · nvm_service ·   |
 |                     params_apply · status · led · wdg_service                                     |
 +---------------------------------------------------------------------------------------------------+
 | core/  (C/C++, uses ONLY hal_*.h — compiled for the target AND for the host twin)                  |
 |   motion (glue of motion_sm + homing + stepgen core) · safety (control tick: latches, timeouts,    |
 |   debounce, events) · afe (sample handling, load limit) · link (parser, TX queues, stop sniffer)  |
 |   · cmd (dispatcher, handlers) · stream (DATA/EVENT/VALID) · cfg (params runtime, NVM service)    |
 +---------------------------------------------------------------------------------------------------+
 | pure/  (C11, no HAL, no globals of other layers — host unit tests, native env)                    |
 |   crc16 crc32 le frame payload cmd_check param_rules nvm_log hx711_seq hx711_math afe_rate        |
 |   loadlim ramp planner units motion_sm homing latches debounce stop_sniff estop_isr(pattern)      |
 | gen/   params_gen.h/.c  (GENERATED by the Integrator from params.yaml — never hand-edited)         |
 +---------------------------------------------------------------------------------------------------+
 | hal/   hal_*.h = the HOST-TWIN SEAMS (§8): uart · time · stepgen · inputs/outputs · afe · flash ·  |
 |        sys(wdg, reset cause, uid, crit)                                                            |
 |   hal/f446/  register-level target implementation (LL/CMSIS): clock, gpio/exti shims, tim2        |
 |              stepgen, tim5 time+tick, usart2+dma, hx711 bit-bang shim, flash_f4, iwdg, faults      |
 |   (twin implementation of hal_*.h: Integrator, 00_System/tools/fw_twin/ — not in 02_FW)           |
 +---------------------------------------------------------------------------------------------------+
 | stm32duino core 4.30000.0 (startup, HAL_Init, SysTick/millis) · CMSIS · STM32F4 HAL/LL headers    |
 +---------------------------------------------------------------------------------------------------+
```

Principles (each traced in §9):
1. **Raw data out, safety in** (SYS-002): the FW streams raw counts and the commanded position; every FW safety function (E-stop sense, STOP/PAUSE buttons, limits, FW load limit, AFE stale, link watchdog, jog dead-man, idle disable, IWDG) works with the PC absent and the stream off. No force scaling in FW.
2. **Stops are hardware-first**: every immediate stop is one call of the stop primitive `sg_halt()` (§5.3) executed **inside the ISR that detects the cause** (E-stop/limit/STOP EXTI, HX711 ISR, step ISR) — never deferred to the main loop. Controlled stops are requested to the step ISR within one control tick (≤ 1 ms).
3. **Motion disabled by default** (CLAUDE.md, D-13, SAF-FW-018): after any reset the axis is "not enabled, not homed"; no PUL edge until ENABLE + settle; ENA itself stays at "no current" (driver holding) unless the E-stop is active.
4. **No dynamic allocation** (NFR-005), no exceptions/RTTI, no `printf`, no `HardwareSerial`/`HardwareTimer`/`attachInterrupt`/`Wire`/HX711 libraries. The link check (`tools/check_map.py`) fails the build if `malloc`, `_sbrk`, `operator new`, `HardwareSerial`, `HardwareTimer` or `printf` are linked.
5. **No blocking > 1 ms in the main loop** (NFR-006) except the NVM erase/program pass (idle only, ≤ 0.6 s). All waits (ENA settle, DIR setup, link TX quiesce) are deadlines checked per pass, not spins; the only spins are the HX711 SCK timing (≤ 1 µs) and the bounded clock start at boot.
6. **All decision logic is pure and host-tested** (`src/pure/`): ramp, planner, units, motion and homing state machines, latch/clear rules, debounce, load-limit compare, command checks, frame parser, NVM log codec, stop sniffer. ISR bodies are thin: read hardware → call a pure function → write hardware.
7. **Only the HAL layer touches registers**; `core/` and `pure/` compile unchanged in the host twin (D-07, SYS-008).

## 3. Clock, boot sequence and safe state

### 3.1 Clock override (FW-PLT-002)
`extern "C" void SystemClock_Config(void)` in `hal/f446/clock.cpp` (strong; called by the core in `hw_config_init()` after `HAL_Init()`, VERIFIED `SrcWrapper/src/stm32/hw_config.c:90-95`):
1. `RCC->CR |= HSEBYP | HSEON`; poll `HSERDY` with a **5 ms** DWT timeout (DWT is initialised by the core before `HAL_Init`, VERIFIED `hw_config.c:85-87`).
2. HSE ready → PWR scale 1; PLL M = 4, N = 180, P = 2, Q = 8, source HSE; `PLLON`, wait `PLLRDY` (2 ms bound); over-drive on (`ODEN`, `ODRDY`, `ODSWEN`, `ODSWRDY`, bounded); `FLASH->ACR` = 5 WS + PRFTEN + ICEN + DCEN; HPRE /1, PPRE1 /4, PPRE2 /2; `SW = PLL`, wait `SWS`.
3. Any timeout → HSE off, same PLL from HSI (M = 8) → identical bus clocks (pinout §3); `g_clk_fallback = 1` → `CLK_FALLBACK` status flag + EVENT at link start (R3 P7).
4. `SystemCoreClockUpdate()`; `HAL_InitTick(TICK_INT_PRIORITY)`.
5. Clock security system (CSS) on in the HSE case; `NMI_Handler` clears `CSSC` first, forces the safe outputs (`sg_halt(TRUNCATE)`), records the cause in `.noinit`, resets → next boot runs on the HSI fallback.

All derived constants (TIM2 tick 90 MHz, TIM5 prescaler, USART BRR, HX711 spin cycles, DWT µs) are computed at init from `HAL_RCC_GetPCLK1Freq()/GetPCLK2Freq()/SystemCoreClock` (FW-PLT-002, R1 B-02).

### 3.2 Boot sequence (`app_init()`)

| Step | Action | Time after reset |
|---|---|---|
| 0 | Reset: all pins Hi-Z (PB4 = NJTRST AF0 with PU, PA13/14 SWD). Driver inputs see **no LED current**: PUL idle, DIR "0", **ENA = driver enabled/holding** (D-13); RATE held at 80 SPS by its external pull-up | 0 |
| 1 | core startup (`.data/.bss`, `.RamFunc` copied) → `premain()` (NVIC group 4) → `HAL_Init` → §3.1 clock (≤ 5 ms HSE wait + ≤ 4 ms PLL) | ≤ 10 ms |
| 2 | Reset cause from `RCC->CSR` (LPWR, WWDG, IWDG, SFT, POR, PIN, BOR) then `RMVF`; fault record from `.noinit` (magic + CRC) | µs |
| 3 | Stack painting; DWT; all NVIC priorities (pinout §4) set **before** any IRQ is enabled; TIM5 time base started (no IRQ yet) | µs |
| 4 | `params_set_defaults()` → `nvm_boot_load()` (scan both NVM sectors, newest valid record, migration by id, hard-rule check, §5.11) | ≤ 2 ms |
| 5 | **Inputs**: GPIO inputs with internal pull-ups (backup to the external ones), `SYSCFG->EXTICR` routing, edge selection (both edges), **read initial levels**: E-stop open → ESTOP latched (src = boot); START/END open → LIMIT latched/reported; both → LIMIT_WIRING; STOP open (per `io.stop_active_level`) → HALT latched (src = button); ALM/PEND/DRV_PWR sampled (SAF-FW-007, SAF-FW-018) | µs |
| 6 | **Outputs** (ODR written before MODER): **ENA** = disabled level if the E-stop input is active, else the "no current" level (= enabled/holding, D-13) according to `motion.ena_invert`; **DIR** = 0; **PUL**: TIM2 configured with OC1 *forced inactive*, then PA0 → AF1 (pin at idle level); **SCK** low; **RATE** per `afe.rate_sps`; TRIP low; LED; unused pins analog | ≤ 12 ms |
| 7 | Motion state "not enabled, not homed" (SAF-FW-018); stream off (FW-STR-001); `pos_steps = 0` | – |
| 8 | Link: USART2 + DMA1 S5/S6, parser, TX queues; EVENT BOOT(reset cause), CLK_FALLBACK, NVM result (defaults / migrated) | – |
| 9 | AFE: EXTI4 enabled, settle-discard armed (FW-AFE-003) | – |
| 10 | EXTI lines of the inputs enabled (pending bits cleared first; the boot latches of step 5 already cover active inputs) | – |
| 11 | Control tick (TIM5 CC1, 1 kHz) enabled | – |
| 12 | IWDG started, run window 32–90 ms (§5.13) | ≈ 15 ms |
| 13 | `loop()` | – |

Rationale for keeping the driver outputs Hi-Z until step 6: Hi-Z is exactly the reset state (no LED current), and the polarity parameters are only known after step 4; driving a guessed level earlier could briefly *disable* a holding driver (with `ena_invert` = 1). Reset → step 6 ≤ 15 ms, during which nothing can pulse.

### 3.3 Safe state per situation (SRS §3.2 rows "MCU reset", "E-stop")

| Situation | PUL | DIR | ENA | Notes |
|---|---|---|---|---|
| Reset → boot step 6 | Hi-Z (idle, no LED current) | Hi-Z | Hi-Z = enabled/holding (D-13) | external 10 kΩ pull-downs (optional) define the node |
| Boot, E-stop open | idle | 0 | **disabled level** | SAF-FW-018 |
| Idle / not enabled | idle (OC1 forced inactive, CEN = 0) | last | per state | – |

| E-stop sense open | idle immediately (pulse in flight truncated) | unchanged | **disabled** ≤ 1 µs after ISR entry | SAF-FW-005 |

| NVM erase (idle only) | idle | – | per state; E-stop ISR still active (RAM-resident, §5.11) | FW-NVM-003 |

## 4. Scheduling model

### 4.1 Execution contexts

| Context | Level | Trigger / rate | Work | Budget |
|---|---|---|---|---|
| `EXTI15_10_IRQHandler` (RAM) | 0 | E-stop sense edge | open → `sg_halt(TRUNCATE)`; ENA → disabled (one BSRR write); latch ESTOP + t_us; closed edge → note t_us for the release debounce | ≤ 0.5 µs |
| `EXTI0/EXTI1_IRQHandler` (RAM) | 1 | START/END edge | active edge: `sg_halt(CLEAN)` (unless expected by an idle state, §5.2); capture `pos_steps` + t_us (homing edge); latch; mask own line | ≤ 1 µs |
| `EXTI9_5_IRQHandler` (RAM) | 1 | STOP (7), PAUSE (6), ALM (8) | STOP active: `sg_halt(CLEAN)`, latch HALT(src = button), mask line; PAUSE active: set request + t_us; ALM: latch level + t_us | ≤ 1 µs |
| `TIM2_IRQHandler` | 2 | each update = each completed PUL pulse | count step, next period from the pure ramp, end / OPM handling, stop requests, overrun check (§5.6) | ≤ 1.2 µs |
| `EXTI4_IRQHandler` | 3 | HX711 DOUT falling (80 Hz) | t_us + position + motion flags latch, bit-bang read, rails/load-limit/MOVE_UNTIL_LOAD check (→ `sg_halt(CLEAN)`), push sample to the AFE ring (§5.8) | ≤ 55 µs |
| `TIM5_IRQHandler` (CC1) | 4 | 1 kHz control tick | §4.3 | ≤ 30 µs typ, ≤ 60 µs worst |
| `DMA1_Stream5/6`, `USART2`, SysTick | 5 | RX laps, TX chunk done, line errors, HAL tick | lap counter; chain next TX chunk (high class first); error counters | ≤ 2 µs |
| main loop | thread | continuous | §4.2 | ≤ 1 ms per pass |

### 4.2 Main loop (one pass, `app_loop()`)

```
t0 = time_us()
link_poll()          RX DMA bytes -> frame parser -> cmd_dispatch() for every complete frame,
                     stop after 500 µs of handler time (rest next pass); STOP/HALT are idempotent and also
                     executed by the tick's stop sniffer (§5.9.3)
afe_drain()          AFE ring -> DATA frames (one per conversion) -> TX class N; fallback frames (§5.14)
events_flush()       EVENT ring -> TX (≤ 4 per pass)
status_service()     stack high-water (every 100 ms), loop_max_us, counters
params_apply()       re-configuration of changed groups (AFE gain/rate, input polarity, motion limits)
nvm_service()        SAVE / LOAD / DEFAULTS when requested and idle (§5.11; the save pass is excluded
                     from loop_max_us)
led_service()
wdg_service()        IWDG kick only if the control tick advanced since the last kick (§5.13)
loop_max_us = max(loop_max_us, time_us() - t0)
```
Budget: link ≤ 500 µs + DATA build ≤ 30 µs + events ≤ 40 µs + rest ≤ 50 µs ≈ 620 µs, plus ISR preemption (≤ 5 % step CPU at 50 kHz + tick ≤ 3 % + HX711 0.5 %) → **≤ 0.7 ms ≤ 1 ms** (NFR-006, §6).

### 4.3 Control tick (TIM5 CC1, 1 kHz, level 4)

```
 1  CCR1 += 1000; tick_count++; ms++ (u32 ms time base for long timeouts, 49.7 days)
 2  sample all input levels (one IDR read per port) -> pure debounce:
      release / re-arm of masked EXTI lines after `input.release_ms` (20 ms) or `input.estop_release_ms`;
      backup detection: input active while not latched (missed edge) -> same action as the ISR
 3  stop sniffer on new RX bytes (§5.9.3) -> PC STOP/HALT executed here at the latest
 4  fold ISR latch records (atomic snapshot) into pure latches.c -> latch states, VALID auto-clear, EVENTs
 5  timeouts (pure, §5.7): link watchdog, jog dead-man, AFE stale, idle disable, ENA settle, DRV_PWR
 6  PAUSE request -> controlled stop / RESUME_REQUEST event
 7  motion_sm step: homing phase transitions, MOVE_DONE, start of the next segment, retargets
 8  ALM / PEND / DRV_PWR edges -> EVENTs (no stop of a running move, D-16; feed the D-28 start-block)
 9  AFE missed-edge recovery: DOUT low and no read for 2 periods -> EXTI4 SWIER (TS pattern)
10  fallback-frame request at `stream.fallback_hz` while AFE stale
```
The tick never touches the UART or flash; it hands EVENTs and frame requests to the main loop through SPSC rings.

### 4.4 Data sharing rules
- **ISR → tick latch records**: each input/AFE/step ISR owns one record `{volatile u8 flags; u32 t_us; i32 pos}` written only by that ISR; the tick reads it under `CRIT_HALT` (≤ 0.2 µs) and clears the "new" bit. No ISR ever posts an EVENT directly.
- **AFE ring** (EXTI4 → main): 16-slot SPSC ring `{t_us, raw, pos_steps, flags, seq}` with `__DMB()` before the index publish (TS P9).
- **Step-generator descriptor** (thread/tick → step ISR): written only while the timer is stopped, or as a small "retarget" record under `CRIT_MOTION` (BASEPRI 0x20, ≤ 1 µs); the step ISR reads it at its next update.
- **`pos_steps`** (int32): written only by the step ISR (and by homing's zero shift under `CRIT_MOTION` while stopped); 32-bit aligned reads are atomic on the M4.
- **Thread ↔ tick** (motion requests, latch clears, event ring producers): `CRIT_TICK` (BASEPRI 0x40).
- **TX queues**: producers = main loop only; consumer = DMA1 Stream6 TC ISR (level 5).

## 5. Module designs

### 5.1 `hal/f446` system: time base, DWT, reset cause, faults, stack, UID
- **TIM5** 32-bit, PSC = 89 → **1 MHz**, free-running, wraps every 71.6 min: `t_us` of DATA, EVENT and SET_VALID (FW-TIM-001). CC1 compare = control tick (no pin). The counter runs through flash stalls (hardware), so time is never lost.
- `time_ms()` = tick-maintained u32 (long timeouts: idle disable up to 65 535 s, link age).
- DWT `CYCCNT`: `dwt_spin_cycles()` for the HX711 SCK phases; profiling of ISR durations (`dbg_cycles[ctx]` in the debug image; NFR-007 measurement).
- Reset cause: `RCC->CSR` bits → ICD bit order (pending); `RMVF`.
- HardFault/NMI: safe outputs (`sg_halt(TRUNCATE)`), record PC/LR/CFSR in `.noinit`, `NVIC_SystemReset()`; the record is reported as an EVENT/LOG after reboot.
- Stack: painted at boot, lowest unpainted word every 100 ms → GET_STATUS `stack_free_min` (NFR-005).
- UID: 12 bytes at 0x1FFF7A10 (ASSUMED, RM0390 — verify at WP1).

### 5.2 Inputs: E-stop sense, limits, STOP/BREAK, PAUSE, ALM, PEND, DRV_PWR

| Input | Pin / EXTI / level | Active | Polarity | First-edge action (ISR) | Release / re-arm | Req. |
|---|---|---|---|---|---|---|
| E-stop sense | PA10 / 10 / 0 | high (NC open) | **fixed** | `sg_halt(TRUNCATE)`, ENA disabled, latch ESTOP | closed continuously ≥ `input.estop_release_ms` (100 ms) enables ESTOP_CLEAR | SAF-FW-005/006/007, FW-SW-002 |
| START / END | PB0, PC1 / 0, 1 / 1 | high | **fixed** | if moving (or homing seek): `sg_halt(CLEAN)`, capture pos + t_us; latch LIMIT_x (or homing edge); mask line | stable inactive ≥ `input.release_ms` (20 ms) → line re-armed; latch auto-clear rule §5.4 | FW-SW-001, SAF-FW-013/014 |
| STOP/BREAK | PC7 / 7 / 1 | `io.stop_active_level` (default open-active, NC) | param | `sg_halt(CLEAN)` (any state), latch HALT(src = button), mask line | released ≥ 20 ms → re-arm; HALT_CLEAR accepted only when released ≥ 20 ms | SAF-FW-022, FW-SW-003 |
| PAUSE | PB6 / 6 / 1 | `io.pause_active_level` (default closed-active, NO) | param | request flag + t_us, mask line | released ≥ 20 ms → re-arm | SAF-FW-023, FW-SW-003 |
| ALM | PA8 / 8 / 1 | `drv.alm_active_level` | param | level + t_us latch; no stop of a running move (D-16); **new motion refused while ALM active and DRV_PWR on (D-28)**. In the current open-loop driver setting (D-27) ALM has no following-error source | – | FW-SW-004, D-28 |
| PEND | PA9 / polled | `drv.pend_active_level` | param | tick sample → status bit | – | FW-SW-004 |
| DRV_PWR | PA7 / polled | low = powered | fixed | tick sample → status bit, EVENT on change; restarts the ≥ 500 ms settle after power returns; input to the ALM start-block | stable ≥ 20 ms | D-28 (OI-FW-06) |

Rules:
- **Act on the first edge, debounce only the release** (FW-SW-001, R4 §3.4). After the first active edge the ISR masks its own EXTI line (bounce produces no further interrupts, no ISR storm); the tick polls the pin at 1 kHz and re-arms the line after the stable release. Re-arming clears the pending bit first and re-reads the level (an input that became active again during the re-arm is caught by the tick's backup detection).
- Both edges are enabled on every line; the ISR reads the pin level and acts only on the active level. This keeps the EXTI configuration independent of the polarity parameters of STOP/PAUSE/ALM (a polarity change re-evaluates the current level in the tick, `params_apply`).
- Fixed polarity for E-stop and limits: no parameter exists (SAF-FW-007, FW-PAR-006). Internal pull-ups are enabled as a backup to the external ones (wire break reads active even without the input cell).
- Both limits active simultaneously → LIMIT_WIRING (SAF-FW-014), evaluated in the ISR (other pin read) and in the tick.
- Expected limit edges during HOME are routed to the homing machine (§5.5) instead of a LIMIT latch; the ISR still stops immediately and captures the position.

### 5.3 Stop primitive, latches and the stop policy (SRS §3.2)

**`sg_halt(mode)`** (`hal/f446/stepgen_tim2.cpp`, `.RamFunc`, executed under `CRIT_HALT` ≤ 0.2 µs; the decision part is pure `stepgen_halt_decide()`):

| Mode | Used by | Action |
|---|---|---|
| **TRUNCATE** | E-stop sense, HardFault/NMI | `OC1M = force inactive` (output idle at once), `CEN = 0`, `UIE = 0`; if `CNT ≥ CCR1` a pulse was in flight → it is truncated and **not counted** → `pos_uncertain = 1`. (HOMED is cleared by the E-stop anyway.) |
| **CLEAN** | limits, STOP/BREAK button, PC STOP/HALT, FW load limit, AFE fault, MOVE_UNTIL_LOAD, homing edges, step fault (from the tick) | read `CNT`: if `CNT ≥ CCR1 − guard` (pulse running, or starting within `guard` = 0.5 µs) → set `OPM = 1`: the counter stops by hardware at the update that ends **this** pulse (≤ pulse width + guard later), the update ISR counts it → **no runt, no uncounted pulse**; else → `OC1M = force inactive`, `CEN = 0` → no further pulse. |

Consequences: the last PUL edge after a CLEAN stop is ≤ `pulse_high` + 0.5 µs after the halt (≤ 10.5 µs default, ≤ 100.5 µs at the parameter maximum), which fits the 200 µs / 2 ms budgets of SAF-FW-002 in every case; SAF-FW-004 "no runt, counter = completed pulses" holds for every stop except the E-stop TRUNCATE (flagged ±1 step, axis not homed afterwards anyway). The E-stop uses TRUNCATE because its budget is 100 µs and a maximum-width pulse could exceed it.

**Race-free start ("start-then-recheck")**: starting the timer (thread or tick, under `CRIT_MOTION`) captures the global `stop_gen` counter (incremented by every `sg_halt`), checks all gates, writes `CEN = 1`, then re-reads `stop_gen`; if it changed, it calls `sg_halt(TRUNCATE)` itself. No pulse can have started: the first active edge comes ≥ `dir_setup` (20 µs) after `CEN` (§5.6). The step ISR never sets `CEN` and never clears `OPM` (only the start does), so a halt cannot be undone by a preempted step ISR (pattern of TS F-01 / DEF-M3r1-01: a stop must also discard the target and ramp state, R3 P11).

**Latch model** (pure `latches.c`, folded in the tick; table = SRS §3.2):

| Latch | Set by | Pulses | ENA | Clear | HOMED | VALID |
|---|---|---|---|---|---|---|
| ESTOP | E-stop ISR (or boot) | TRUNCATE | disabled | input closed ≥ 100 ms **and** ESTOP_CLEAR; afterwards driver stays disabled | cleared | cleared |
| HALT(src = PC / button) | HALT cmd / STOP ISR | CLEAN | kept | HALT_CLEAR (button: also released ≥ 20 ms) | kept | cleared |
| PAUSED | PAUSE button / GUI Pause | controlled | kept | next accepted motion command or PC clear | kept | cleared |
| LIMIT_START / LIMIT_END | limit ISR while moving | CLEAN | kept | auto: released ≥ 20 ms **and** moved away | kept | cleared |
| LIMIT_WIRING | both active | CLEAN | kept | FAULT_CLEAR when both released | kept | cleared |
| LOAD_LIMIT | HX711 ISR | CLEAN | kept | FAULT_CLEAR (also beyond threshold; re-trip on regrow) | kept | cleared |
| AFE_FAULT | tick (stale while moving) | CLEAN | kept | FAULT_CLEAR after fresh samples | kept | cleared |
| LINK_WDG | tick | controlled | kept | next CRC-valid frame | kept | cleared |
| STEP_FAULT | step ISR / tick | CLEAN | kept | FAULT_CLEAR | **cleared** | cleared |
| HOME_NOT_FOUND / HOME_WIRING / HOME_ABORTED | homing | CLEAN | kept | FAULT_CLEAR | cleared | cleared |
| (jog dead-man) | tick | controlled | kept | – (not latched) | kept | unchanged |
| (idle disable) | tick | – | disabled | re-ENABLE | cleared | – |
| (PC STOP) | STOP cmd | CLEAN or controlled (mode) | kept | – (not latched) | kept | cleared |

Every stop discards the active move target and ramp state, clears VALID with a cause, and posts an EVENT with the cause (SAF-FW-001); no stopped move is ever resumed by the FW.

### 5.4 Motion state machine (pure `motion_sm.c`, glue `core/motion.cpp`)

State = `{drive: NOT_ENABLED | ENABLING | ENABLED, activity: IDLE | MOVING(kind) | STOPPING, homed, pos_uncertain, latches, paused}`; `kind ∈ {MOVE_ABS, JOG, MOVE_UNTIL_LOAD, HOME(phase)}`. "Driver enabled" in the SRS sense = `drive == ENABLED`; the physical ENA level is a separate output (§3.3).

| Command / event | Pre-conditions (NACK reason, check order per FW-CMD-001) | Effect |
|---|---|---|
| ENABLE | not ESTOP latched, E-stop input closed (E_ESTOP) | ENA → enabled level; `ENABLING` until `motion.ena_settle_ms` (**default 500 ms**, D-28; SRS v0.2 still says 200 ms → OI-FW-01) **and** ≥ settle after DRV_PWR came on; then `ENABLED` + EVENT |
| DISABLE | not moving (E_BUSY) | ENA → disabled level, `NOT_ENABLED`, HOMED cleared, EVENT |
| MOVE_ABS(target µm, v, a) | enabled; no latch (ESTOP/HALT/fault); AFE fresh and not saturated; homed (E_NOT_HOMED); target in soft limits (E_RANGE); v ≤ min(`v_max`, step-rate cap), a ≤ `a_max` (E_RANGE); not moving (E_BUSY); not toward an active/latched limit | plan (pure planner) → start step generator; MOVE_DONE(final pos, reason) at the end |
| JOG(signed v) | as MOVE_ABS but un-homed allowed at ≤ `v_unhomed`; JOG while jogging = retarget speed (virtual index) + dead-man refresh; JOG(0) = controlled stop | target = soft limit in that direction (homed) or start ± `home.max_travel_um` (un-homed) — the jog can never pass it |
| MOVE_UNTIL_LOAD(dir, v, a, raw_stop, bound) | as MOVE_ABS (homed) | jog-like move to `bound`; the HX711 ISR stops on the first sample beyond `raw_stop` (§5.8); MOVE_DONE(reason LOAD / BOUND) |
| HOME(confirm flag) | enabled, no latch, AFE fresh; abs(raw − `zero_raw`) ≤ `home.max_load_raw` unless confirmed (SAF-FW-021) | §5.5 |
| STOP(mode) | always accepted, idempotent | immediate → `sg_halt(CLEAN)`; controlled → decel with `a_stop`; not latched; VALID cleared |
| HALT / HALT_CLEAR | always accepted, idempotent / clear only if the button is released ≥ 20 ms | §5.3 |
| ESTOP_CLEAR | input closed ≥ 100 ms, else NACK with the input state | clears ESTOP; driver stays disabled, not homed (SAF-FW-006) |
| FAULT_CLEAR | per latch cause gone (LOAD_LIMIT always clearable); else NACK naming the remaining cause | FW-CMD-003, SAF-FW-011 |
| `steps_per_mm` SET | idle only (E_BUSY) | positions rescale, HOMED kept (zero is a step count, FW-MOT-009) |

Gating is a pure function `motion_gate(state, cmd) → (status, detail)` used by `cmd_check` (FW-CMD-001 order: type → length → args → **state** → execution). Every refusal reason of SAF-FW-020 has its own NACK code/detail (ICD pending) and a host vector.

Direction convention: machine coordinate x increases away from the START (home) switch; "toward START" = negative step direction; `dir_invert` maps it to the DIR level. A swapped DIR or switch is detected by HOME_WIRING (§5.5).

**ALM start-block (D-28, extends D-16):** every *new* motion command (ENABLE excluded; JOG refresh of a running jog excluded) is refused (NACK, detail = ALM) while ALM is active **and** DRV_PWR reports driver power; a running move is **not** stopped by ALM. One pure gate term in `motion_gate()`; requirement text pending in the SRS (OI-FW-06). Proposed in addition (R5 §1.5, not yet decided): DRV_PWR off → motion refused and HOMED cleared (driver power lost = position lost, D-11).

### 5.5 Homing (pure `homing.c`; FW-HOM-001/002, R4 §3.1)

| Phase | Motion (all via the step generator) | Exit |
|---|---|---|
| 0 PRECHECK | – | enabled, no latch, load check (SAF-FW-021) → 1 or 2; else NACK |
| 1 RELEASE | if the home switch is active: move away at `v_slow` until released (debounced 20 ms), then `backoff_um` further | → 2 |
| 2 SEEK_FAST | toward the home switch at `v_fast`, accel `home.a_um_s2`, travel bound `max_travel_um` | home-switch edge (ISR: CLEAN stop) → 3 · bound → HOME_NOT_FOUND · opposite switch → HOME_WIRING |
| 3 BACKOFF | away at `v_slow` until released, then `backoff_um` | → 4 |
| 4 APPROACH_SLOW | toward the switch at `v_slow` (≤ `v_fast`/10) | **first** edge: the EXTI ISR captures `pos_steps` (exact, bounce-free) and stops → 5 |
| 5 SET_ZERO | `pos_steps -= pos_edge + um_to_steps(offset_um)` under `CRIT_MOTION` (timer stopped) — the edge lies at −`offset_um` | → 6 |
| 6 MOVE_TO_0 | move to 0 (expected: the switch is released on the way) | → DONE: HOMED = 1, `pos_uncertain` = 0, EVENT HOMED |
| any | any stop/latch/fault/PC STOP | HOME_ABORTED (stop already done), not homed |

Repeatability (FW-HOM-003, target only): at `v_slow` = 0.5 mm/s an ISR latency of ≤ 2 µs is 1 nm; the switch (±5…20 µm, A-12) dominates.

### 5.6 Step generator (TIM2 PWM mode 2; FW-MOT-001…003, SAF-FW-004; R4 §1.3–1.6)

**Hardware** (pinout §2): TIM2, f_tick = 90 MHz (PSC 0), `ARR = c − 1`, `CCR1 = c − PW`, **PWM mode 2** (output inactive while CNT < CCR1, active for the last PW ticks) → **the pulse ends exactly at the update event**; `ARPE = OC1PE = 1` (period and compare change together at the update); `CC1P = pul_invert`; `UIE`.

**Pulse timing from parameters** (FW-MOT-001): `PW = round(pulse_high_ns · f_tick)` (10 µs → 900 ticks); `c_min = max(ceil(f_tick / max_step_rate_hz), PW + ceil(pulse_low_min_ns · f_tick))` (50 kHz → 1800 = 900 + 900); hard rule `1e9/max_step_rate ≥ high + low` is checked by `param_rules`. The effective speed cap is min(`v_max_um_s`, `max_step_rate_hz`·1000/`steps_per_mm`) (FW-MOT-009).

**Start** (thread/tick, `CRIT_MOTION`): DIR may be written only while the timer is stopped. Set DIR, then `CNT = 0`, preload the first period with `CCR1_first = max(c1 − PW, dir_setup_ticks)` and `ARR = CCR1_first + PW − 1` (the first active edge is ≥ `dir_setup_us` after the DIR write — no busy-wait), second period preloaded after `EGR.UG`, clear `UIF`, `OPM = 0`, `OC1M = PWM2`, `CEN = 1`, re-check `stop_gen` (§5.3). DIR was set at least `dir_setup` before because the start itself happens after the DIR write. In practice c1 is ≫ 20 µs (from rest c1 = f·√(2/α) ≥ 1 ms for every parameter combination in range).

**Update ISR body** (`stepgen_on_update()`, pure core `sg_step()`):
```
clear UIF
pos_steps += dir; steps_done++                       // the pulse just completed (PWM mode 2)
if halting (OPM set by sg_halt CLEAN): finalise -> STOPPED, report reason; return
if steps_done == N: finalise (the counter already stopped via OPM armed one step earlier) -> MOVE_DONE
c = ramp_next(&ramp)                                  // exact sqrt ramp, max rule, fractional carry (R4 §1.5)
write ARR = c - 1, CCR1 = c - PW                      // preload for the period AFTER the one now running
if steps_done == N - 1: OPM = 1                        // hardware stops at the end of the last pulse: no deadline
apply pending retarget (jog speed / controlled stop: virtual index, r = min(r, ceil(v²/2a_stop)))
overrun check: UIF set again at exit -> STEP_FAULT (CLEAN halt via flag; tick clears HOMED)
```
Exact counting (SAF-FW-004): `pos_steps` changes only here (plus the homing zero shift while stopped); one update = one completed pulse. The last step of a move is ended by OPM in hardware, so there is no "stop in time before the next pulse" deadline (fixes Stefan B-07). A missed update (ISR delayed by more than one period, only possible far above 50 kHz) is detected by the `UIF`-at-exit check → STEP_FAULT, HOMED cleared (SAF-FW-004). Diagnostic option (SRS §8 deferred): TIM3 slave counter on TIM2 TRGO compared after each move.

**Ramp** (pure `ramp.c`, R4 §1.5): `c_k = max(C_a/(√k + √(k−1)), c_min, C_d/(√r + √(r−1)))` in float32 with the fractional carry `acc += c; c_int = (u32)acc; acc -= c_int`; √(k−1) re-used from the previous step (1 VSQRT + 1 VDIV per ramp step); cruise steps add the constant `f/v`. Host vectors R4 TV-M (5.2 s trapezoid = 468 000 000 ticks, triangle, asymmetric triangle): every period within ±1 tick, sum within ±N/1000 ticks (FW-MOT-003). Velocity mode / on-the-fly changes / controlled stop use the **virtual index** (`k₀ = v₁²/2α`, decel `r` from `v₁²/2α_d`). Planner (pure `planner.c`): trapezoid/triangle kind, n_acc/n_dec, duration — used for MOVE_ABS acceptance (step-rate cap) and the MOVE_DONE timing check of the twin.

**Controlled stop ≤ 2 ms (SAF-FW-003)**: the tick posts the request; the next update ISR switches to the decel term. If the current step period is longer than 1 ms (very slow motion), the request would not take effect within the budget — in that case the stop distance `v²/(2·a_stop)` is < 1 step for all practical parameter values (e.g. 160 steps/mm, a_stop 1 m/s²: < 0.8 step) and the tick issues `sg_halt(CLEAN)` instead (OI-FW-07 for the Validator's interpretation).

**Slowest step rate**: 32-bit ARR at 90 MHz → max period 47.7 s → **≥ 0.021 steps/s**. SYS-004's 0.001 mm/s therefore needs `steps_per_mm` ≥ 21 (true for 160/800/1280; the proposed dictionary range down to 1 step/mm is not fully usable at the slowest speeds → speeds below the floor are refused with E_RANGE, OI-FW-05).

**ENA** (FW-MOT-008): set only by ENABLE/DISABLE/idle disable/E-stop; never by an operational stop (D-10/D-11). The settle time is a deadline in the motion state machine, not a delay.

### 5.7 Safety supervisor timeouts (control tick, pure functions)

| Function | Rule | Action | Req. |
|---|---|---|---|
| Link watchdog | moving **and** now − `last_valid_rx_ms` ≥ `safety.link_timeout_ms` (1000) | controlled stop, LINK_WDG, VALID cleared, EVENT; clears at the next CRC-valid frame | SAF-FW-015 |
| Jog dead-man | JOG active and no JOG refresh for `motion.jog_timeout_ms` (250) | controlled stop, EVENT (not latched, VALID unchanged) | SAF-FW-016 |

| Idle disable | `safety.idle_disable_s` ≠ 0, idle that long **and** abs(raw − `zero_raw`) < `release_band_raw` | ENA disabled, HOMED cleared, EVENT; with load ≥ band: stays enabled indefinitely | SAF-FW-017 |
| ENA settle | `ENABLING` until deadline | → `ENABLED` | FW-MOT-008 |
| Limit latch auto-clear | released ≥ 20 ms and moved away | clear LIMIT_x | SAF-FW-013 |

### 5.8 HX711 driver, load limit and MOVE_UNTIL_LOAD (FW-AFE-001…005, SAF-FW-008…012)

`EXTI4_IRQHandler` (level 3), shim ported from TS `02_FW/src/sens/hx711.cpp`:
```
t = TIM5->CNT                                   // FIRST instruction: data-ready timestamp (FW-AFE-005, ≤ 5 µs)
pos = pos_steps; mflags = motion flags (MOVING, pos_uncertain)       // setpoint latch (A-03)
if DOUT not low: spurious edge -> clear PR, return (TS guard)
EXTI4 masked (DOUT toggles with the data)
raw24 = hx711_shift_in(pulses(gain), &dout_high)  // hx711_seq.h, as-is: per bit
                                                  //   CRIT_AFE{ SCK high; spin 0.5 µs; SCK low }; spin 1 µs; sample
     SCK-high length is measured with DWT; > 50 µs -> "power-down suspected" (FW-AFE-003 re-init)
raw = sign_extend(raw24); sat = raw24 in {0x7FFFFF, 0x800000}
trip = loadlim_check(&ll, raw, sat)               // every sample, every state, cannot be disabled (SAF-FW-008/009)
if trip: sg_halt(CLEAN); latch LOAD_LIMIT        // ≤ 200 µs after data-ready (§6)
if MOVE_UNTIL_LOAD active and raw beyond raw_stop: sg_halt(CLEAN); latch reason LOAD
push {t, raw, pos, mflags, flags(sat, settling, dout error)} to the AFE ring (overflow counted)
clear PR4, unmask EXTI4
```
- **Masking** (FW-AFE-001): only each SCK-high phase is inside `CRIT_AFE` (BASEPRI 0x20, masks levels ≥ 2); the E-stop (0) and limits/STOP/PAUSE (1) stay live. Worst SCK-high = 0.5 µs + level-0/1 ISRs (≤ 1 µs each) ≪ 50 µs. Whole read ≈ 25 × 1.6 µs ≈ 40 µs + ≈ 5 µs overhead ≤ 60 µs.
- **Gain/channel** (FW-AFE-002): 25/27/26 pulses for A128/A64/B32, applied to the next conversion; **rate**: PB5 level (80 → high), changeable without reboot; both trigger `afe.settle_discard` flagged samples (still load-checked, FW-AFE-003).
- **Power-down / reset detection**: SCK-high overrun (DWT) or a gain mismatch symptom → SCK held low, settle discard, `afe_reinit_count++`, EVENT (FW-AFE-003).
- **Rate measurement** (pure `afe_rate.c`): period = Δt_us of consecutive samples; median of the last 16; 0.1 SPS resolution in GET_STATUS; `AFE_RATE_MISMATCH` flag + EVENT when it deviates > `afe.rate_tol_pct` from the configured rate (FW-AFE-004).
- **Load-limit state** (pure `loadlim.c`): thresholds `safety.load_raw_min/max` (validated range/hard rule by `param_rules`, SAF-FW-010), `load_trip_samples` consecutive violations, rails always count (SAF-FW-009); after FAULT_CLEAR the value at clear is stored and a re-trip occurs if the violation grows by > `load_regrow_raw` (SAF-FW-011). Thresholds are settable while moving and take effect from the next sample (copied into the ISR-owned state under `CRIT_MOTION`).
- **Missed-edge recovery** (tick): DOUT low and no read for 2 expected periods → `EXTI->SWIER` (recovers edges lost while EXTI4 was masked).
- **NVM hold**: EXTI4 masked during erase/program; samples lost during the stall show up as a sequence/time gap and a "samples lost" flag on the next frame (FW-NVM-003).

### 5.9 Link (IF-002…005, IF-011, FW-CMD-001)

#### 5.9.1 UART + DMA (`hal/f446/uart2_dma.cpp`)
- USART2 921 600 Bd 8N1, OVER16, BRR from PCLK1 (0x31 → 918 367 Bd, −0.35 %).
- **RX**: DMA1 Stream5 Ch4 circular into a **2 048 B** ring (22 ms at full line rate); HT/TC IRQs only count laps; `hal_uart_rx()` reads `NDTR` and returns the new bytes; overflow (writer laps the reader) → `rx_overruns++` and resync (TS P6). USART line errors (ORE/FE/NE) counted in `USART2_IRQHandler`.
- **TX**: two byte rings, **class H** (512 B: responses to STOP/HALT/ESTOP_CLEAR/HALT_CLEAR/FAULT_CLEAR, stop/fault EVENTs) and **class N** (2 048 B: DATA, other responses, other events). Frames are enqueued whole (never split between rings). DMA1 Stream6 Ch4 sends one chunk of whole frames (≤ 256 B) from one ring; the TC ISR starts the next chunk, **class H first**. DATA is enqueued only if class N keeps room for one maximum response (TS rule); otherwise the frame is dropped, its sequence number still advances and the next DATA carries OVERRUN (FW-STR-004).
- `link_tx_idle()` / `link_tx_quiesce()` for NVM operations (TS A-PM3-F1): no frame may be on the wire when a flash stall starts.

#### 5.9.2 Parser and dispatcher
- Pure `frame.c` (TS, as-is): hunt sync, LEN > max → drop one byte, CRC fail → drop one byte, inter-byte timeout → drop one byte; counters `frames_ok`, `crc_errors`, `len_errors`, `timeout_drops` (IF-003/004). Constants = ICD (pending).
- `cmd_dispatch()`: every CRC-valid command gets **exactly one** response echoing its link sequence number (FW-CMD-001, IF-005); unknown type → NACK; NACK has no side effect; check order type → length → arguments → state → execution (pure `cmd_check` table built from the ICD).
- Handler time budget 500 µs per main-loop pass (§4.2). Long operations (SAVE/LOAD/DEFAULTS) only set a request; the response is sent by `nvm_service()` (≤ 2.5 s, NFR-008).

#### 5.9.3 STOP priority on the receive side — the stop sniffer
SAF-FW-002 requires the last PUL edge ≤ 2 ms after the last byte of a STOP/HALT frame. The main loop alone gives ≤ 1 ms (poll interval) + ≤ 0.5 ms (preceding handlers) — inside the budget but with little margin. Therefore the **control tick also scans the RX bytes that arrived since its last run** with pure `stop_sniff()` (finds sync + TYPE ∈ {STOP, HALT} + LEN + valid CRC within the new window, handles frames split across tick boundaries with a 16-byte carry) and executes the stop itself (`sg_halt(CLEAN)` or the controlled-stop request; HALT latch with src = PC). The main loop later parses the same frame normally and sends the single response; STOP and HALT are idempotent (FW-MOT-007), so the double execution has no further effect. Bound: ≤ 1 ms (tick period) + ≤ 60 µs tick latency + halt ≤ 11 µs ≪ 2 ms. The sniffer never acts on anything but STOP/HALT and never sends.

### 5.11 NVM (FW-NVM-001…003)

**Placement decision (answers Q-R3-04): flash sectors 1 and 2 (0x0800 4000 and 0x0800 8000, 16 KB each), used as a two-sector record log.** Linker script `ldscript/bend_f446re.ld` (derived from the variant script, VERIFIED to use `LD_MAX_SIZE`/`LD_FLASH_OFFSET` symbols): `.isr_vector` in sector 0 (0x0800 0000, 16 KB region), a 32 KB hole for sectors 1–2, code/rodata from sector 3 (0x0800 C000, 464 KB). `check_map.py` fails the build if any load address falls into 0x0800 4000–0x0800 BFFF.

| Option | Erase time (F4 family, ASSUMED R2 §5.5) | Linker | Chosen? |
|---|---|---|---|
| Sectors 1 + 2 (16 KB) | typ 250 ms, **max 500 ms** | custom script, ≈ 15.5 KB of sector 0 unused | **yes** |
| Sectors 6 + 7 (128 KB, R2's proposal) | typ 1 s, max 2 s | trivial (`maximum_size` = 256 KB) | no |

Rationale: the erase is the only operation that stalls the CPU (single bank) and suspends the AFE, the control tick and the link; a 4× shorter worst case keeps SAVE far inside the 2.5 s of NFR-006/008, shortens the IWDG long window and the HX711 sample gap. The 15.5 KB lost in sector 0 is irrelevant (§7: < 70 KB code).

**Record format** (TS `nvm_codec` kept): 32-byte header {magic, layout version, header size, `seq`, entry count, entry size, **dictionary hash**, dictionary version, FW version, payload CRC-32, header CRC-32 written **last** = commit marker} + 8-byte entries `{u16 id, u8 type, u8 0, u32 raw}` for every NVM-flagged parameter. ≈ 50 parameters → ≈ 432 B → **512 B slots**, 32 slots per sector.

**Log rule** (pure `nvm_log.c`): records are appended to the next free slot of the active sector; the valid record with the highest `seq` across both sectors wins. When the active sector is full, the *other* sector is erased and the new record is written there; the old sector keeps its valid records until then → **a power loss at any program or erase step leaves a valid record** (host test: power cut after every program word in the twin flash model, FW-NVM-002). Boot rules (ICD, pending): no valid record → defaults + flag; hash equal → load (out-of-range entries → default, counted); hash different → **migration by id** (same id + type + in range kept); hard-rule violation → defaults. Endurance: 10 000 erase cycles × 32 records × 2 sectors ≈ 640 000 saves ≫ 10 000 (FW-NVM-002, A).

**SAVE pass** (`nvm_service`, idle only — FW-NVM-003):
1. Not moving (else E_BUSY at command time); `link_tx_quiesce()` (wait until both TX rings are empty and the USART is idle, bounded by the backlog wire time, ≤ 30 ms; the IWDG is kicked meanwhile).
2. AFE hold (EXTI4 masked), IWDG long window (§5.13), **copy the vector table to RAM and set VTOR**, `CRIT_NVM` (BASEPRI 0x20).
3. Unlock; erase if needed (`SER`, `SNB`, `STRT`); program the entries, then the header, then the header CRC (`PSIZE` x32); the busy-wait loop runs from `.RamFunc`.
4. Lock; verify both CRCs by reading back; errors → NACK E_NVM, the old record stays valid.
5. Restore VTOR, BASEPRI, IWDG run window; AFE resume with settle discard; `nvm_save_ms` stored; CFG_DIRTY = 0 (single normative definition = ICD, FW-NVM-001); EVENT.

**E-stop during a flash operation**: the level-0/1 handlers (`EXTI15_10`, `EXTI0`, `EXTI1`, `EXTI9_5`), `sg_halt()` and the GPIO writes they use are placed in `.RamFunc`, and the vector table is in RAM during the operation, so an E-stop, limit or STOP edge is served **from RAM while the flash is busy** (only flash *fetches* stall on a single-bank F4). SAF-FW-005 (b) therefore holds in every state including SAVE (to be confirmed by check-list item C-04, OI-FW-09). Durations: program-only SAVE ≈ 108 words × ≤ 16 µs ≈ 2 ms; with erase ≤ 0.5 s + 2 ms.

LOAD = reload the newest record into RAM (no flash write); DEFAULTS = RAM defaults, CFG_DIRTY = 1.

### 5.12 Status LED (PA5 / LD2)
Off = not running; slow blink 1 Hz = idle not enabled; fast blink 4 Hz = enabled not homed; on = homed idle; flicker = moving; double blink = latch active (ESTOP/HALT/fault); triple blink = CLK_FALLBACK. Information only (no requirement).

### 5.13 Independent watchdog (SAF-FW-019)
- Started at boot step 12; **run window**: PR = /8, RLR = 190 → 32.5 ms (LSI 47 kHz) … 89.9 ms (LSI 17 kHz) (LSI range ASSUMED from the F4 datasheets, OI-FW-09). A hang therefore resets the MCU ≤ 90 ms after the last kick; after the reset PA0 is Hi-Z → no further PUL edge (≤ 100 ms, SAF-FW-019).
- Kick: in `wdg_service()` of the main loop **only if the control tick advanced** since the previous kick → a dead main loop, a dead tick or a stuck higher-priority ISR (which blocks both) all stop the kicks (TS pattern, R3 §3.5).
- **NVM long window**: PR = /32, RLR = 4095 → ≥ 2.79 s at LSI max, set immediately before the erase/program and restored afterwards; only while idle (SAF-FW-019 permits it, A-14).
- Debug image: `DBGMCU->APB1FZ` freezes the IWDG on halt (`-DFW_DBG_FREEZE_WDG=1`).
- Reset cause IWDG is reported at the next boot (SAF-FW-018).

### 5.14 Stream, VALID and events (FW-STR-001…006, FW-CMD-002, IF-006/007)
- **One DATA frame per HX711 conversion** (IF-007, FW-STR-002): `afe_drain()` takes each ring entry and builds the frame (layout = ICD §DATA, pending) from: `t_us` (data-ready), payload version, flag byte (bit 0 VALID), raw (i32), setpoint distance = `steps_to_um(pos_steps latched)` (A-03), u16 frame sequence counter, status flags (FW-STR-003 list: VALID, MOVING, HOMED, ENABLED, ESTOP, HALT, PAUSED, LIMIT_START, LIMIT_END, LOAD_LIMIT, AFE stale/saturated/settling, AFE_RATE_MISMATCH, LINK_WDG, STOP button, PAUSE button, ALM, PEND, OVERRUN, `pos_uncertain`; bit positions = ICD).
- **VALID**: SET_VALID(v) records `(v, t_apply = time_us())` and returns `t_apply`; a frame carries v iff its sample `t_us ≥ t_apply` (FW-CMD-002). Every stop/fault/latch clears VALID through the same mechanism with `t_apply` = the stop's timestamp, plus EVENT VALID_CLEARED(cause) once per transition (SAF-FW-001).
- **Sequence counter** (FW-STR-004): +1 per conversion, also when the frame is dropped (TX congestion, NVM stall); the next sent frame carries OVERRUN.
- **Fallback frames** (FW-STR-005): while AFE_STALE, the tick requests frames at `stream.fallback_hz` (10 Hz) marked "no AFE data" (pure `stream_sched` from TS for the fractional rate).
- **EVENT ring** (FW-STR-006): 16 entries `{code, arg, t_us}`, producers tick + main (under `CRIT_TICK`), consumer main; overflow counted in GET_STATUS. Event list per FW-STR-006 (codes = ICD).
- **Stream state** never gates a safety function (FW-STR-001): the AFE ISR, the load limit and all latches run identically with the stream off; `afe_drain()` then discards the samples after updating the status.
