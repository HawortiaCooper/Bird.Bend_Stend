## 1. Strategy and test levels

### 1.1 Principles
1. **Independence.** Validator suites never include Implementer A's test helpers (`test/test_impl_*`, `test/common_impl/*`). Expected values come only from oracles: the shared vectors (`protocol_vectors.json`, `check_vectors.json`), `ref_codec.py`, `ref_cmdcheck.py`, R4 §12 reference values, and validator-owned reference models for non-protocol math (ramp, units, load limit, rate median, NVM log) in `02_FW/test/val_oracles/` (Python, they emit JSON consumed by Unity). Protocol vectors are **never** generated a second time: new protocol scenarios are requested from the Integrator for `gen_vectors.py` (R3 pitfall P12).
2. **One requirement, one acceptance criterion, lean TCs.** IDs `TC-<REQ>-nn`. A parametrised case (states × sources × parameter values) counts once. Every test carries `/* Verifies: <REQ> */` and `/* TC: TC-<REQ>-nn */` (Python: `# Verifies:` / `# TC:`).
3. **Twin results prove logic and ordering, not silicon timing.** The twin executes ISR callbacks atomically in NVIC-level order (FW_design §8.2). Twin timing criteria therefore check (a) that the reaction happens in the detecting context (same virtual event, or the stated tick), and (b) the virtual-time budget. Real latencies are measured only at the hardware gate (§6).
4. **Vectors are consumed in place** and counted: the validator run compares the number of executed vector cases with `len()` of each JSON list (anti-silent-skip check), and refuses to run when `icd_version` / `param_dict_hash` of the vectors differ from `proto_gen.h` / `params_gen.h`.
5. **Every run twice**: fixed order and randomised order/seed (seed recorded), as in Thrust_Stand.
6. **Defects** found against code are `DEF-Mx-nn` (severity, file:line, evidence, fix hint) and observations `OBS-Mx-nn`; this P1 review uses `DEF-P1-nn` / `OBS-P1-nn` (§8).

### 1.3 Twin harness requirements (input to the Integrator; see DEF-P1-02/03)
**v0.3 status:** DEF-P1-02/03 are closed — seam v1.1 is single-sourced in `tools/README.md` and vocabulary v2 is implemented
(M1 subset complete; also `wire`, `chatter`, `world_shift`, `iwdg`, `clk`, `afe sck_overrun / miss_next / raw_script`,

The T-level cases need, beyond `tools/README.md` "world-control vocabulary v1":
- **lock-step clock** with deterministic event order; scenario start time configurable (to test the 2³² µs wrap);
- **time-stamped edge log** of PUL (both edges), DIR and ENA, plus a log of seam calls (`hal_step_stop_now/abort/set_period_now/set_period/arm_last`, `hal_ena_set`, `hal_hx711_config`, `hal_flash_*`) with virtual timestamps;
- **byte-level RX injection at a virtual time** (lock-step; TCP pacing alone cannot place the last byte of a STOP frame at a known instant) and a **wire log** of every TX frame with its first-byte/last-byte virtual times (DATA latency, response time, frame integrity around NVM);
- input models with **bounce/chatter and broken wire for every input** (E-stop sense, START, END, STOP, PAUSE, ALM, PEND, DRV_PWR), independent `estop` and `drv_power` control (K1 weld = E-stop open while power stays on);
- HX711 model controls: stall, single missed edge, rate error, rails, **SCK-high overrun / power-down symptom**, observation of the gain pulse count per read;
- **flash power cut** after program word *n* / during erase *k*, flash write counter;
- **IWDG model** (timeout window from `hal_wdg_set_timeout`, LSI 17…47 kHz selectable) and hang injection in the main loop, the tick, and as a level-1 ISR storm;
- RX DMA ring overflow, TX congestion (class D full), HSE failure flag (`hal_clk_fallback`), reset causes.

### 1.5 What the twin cannot show (v0.3, as-built twin; input for the HG list)
1. **ISR and main-loop durations** are zero (atomic callbacks; `loop_max_us` = 0, `stack_free_min` = seam constant 3072, OBS-M1-06): every µs budget is a twin *ordering/virtual-time* proof only → target OC measurement (§6).
2. **Step counting is the twin's model counter.** `hal_step_count()` returns the twin's count, and `x_true` is derived from it; a HAL counting error cannot exist in the twin. SAF-FW-004 twin evidence therefore covers the core's halt-path choice (CLEAN / TRUNCATE / POS_UNCERTAIN) and the edge-level "no runt" rule; counting integrity on silicon = HG-09 (independent on-chip counter).
3. **World direction follows the FW counter, not the DIR pin**: an inverted DIR wiring or `motion.dir_invert` cannot move the world the wrong way (REQ-C-M2-06). HOME_WIRING is provoked by forcing END active during FAST_SEEK; real direction → HG-28.
4. **Edge times are rounded to 1 ns per edge**; periods are reconstructed per interval as round(Δt · 90 MHz) (exact), never from accumulated world time (TV-M would drift by ≈ −13 µs, OBS-E-M2-01).
5. **HX711 bit-bang** is not modelled: the gain/pulse count is observable only as `hal_hx711_config(gain_pulses)` in `seam_log` (REQ-C-M2-05); SCK-high and read time → HG-05.
6. **Electrical levels, RC delays, opto currents, RAM-resident behaviour during a flash erase** → HG items (§6.5).

## 6. Hardware-gate check list (v0.3: re-planned without oscilloscope / logic analyser — CR-02, D-35 G5)

Merged list as in v0.2 (`wiring.md` C-01…C-23 + SYS-009 + every +H criterion of §3.6). HG-01…HG-28 keep their v0.2
meaning; their **methods** are replaced: the PO has no oscilloscope and no logic analyser (D-35 G5), so every timing value
comes from an **on-chip measurement build** (`HW_MEAS`, §6.3) reading timer captures of looped-back signals (§6.2), from the
**PC**, or from a **multimeter / caliper / dial indicator**; what none of these can show is stated as a residual risk with an
acceptance alternative (§6.6). HG-29…HG-31 are new (measurement-chain self-test, release-image confirmation, loopback hygiene).

### 6.1 Measurement principles and tools
1. **Hardware time, not the code under test.** A target timing budget is measured by timer capture / DMA in hardware,
   never by the reacting FW path reading a clock. FW self-reports (`loop_max_us`, `nvm_save_ms`, EVENT `t_us`) count only
   where the requirement defines them as the measure (NFR-006, SAF-FW-025 logic timing) and are cross-checked where possible.
2. **Reference points.** Event = the electrical edge at the MCU pin node (after the input RC), seen by a second timer
   input jumpered to that node; stop = the last PUL edge at the driver-side node (MCU pin during the direct 3.3 V
   bring-up, buffer output after SYS-011).
3. **Trials.** 100 per path (SRS) with a seeded random phase against the step timer (stimulus MT-7) + 10 real actuations
   of the switch / button; the phase distribution is reported (it must cover the guard window before a pulse: 1.5 µs since FW v0.8.5,
   OBS-RC-7).
4. **Decision with uncertainty u.** PASS if max(measured) + u ≤ budget; FAIL if max(measured) − u > budget; otherwise
   INCONCLUSIVE → repeat in a finer mode or decide under §6.6.
5. **Measured image = release logic.** `HW_MEAS` adds capture / DMA / stimulus code in `hal/f446/meas*.c` only;
   TC-SYS-009-02 proves byte-identical safety handlers and core; HG-30 repeats the functional safety items on the release
   image.
6. **Common clock.** All on-chip timers share the PLL; absolute accuracy is established once against the PC (HG-02), and
   every budget has more than 2× margin over a 0.1 % clock error.

### 6.8 Bench safety procedure for stimulus trials on the E-stop sense input (proposal for PO approval, v0.4)
Applies to every trial in which the E-stop sense input (PA10) is driven by the stimulus output instead of the red button:
HG-10 a, HG-04 a, HG-29 e (E-stop input). During these trials the button's **MCU channel is out of service**; with D-41
there is no contactor, so the only stop means independent of the FW under test are the **D-42 hardwired ENA disable**
(the button's NO contact stays wired and active, it does not use the sense input) and the **48 V PSU mains switch**.

| Step | Action | Check / record |
|---|---|---|
| P-1 | Preconditions: no specimen, no load on the table, no tool in the travel; two persons — operator at the PC, observer at the operator panel within reach of the red button and the PSU switch; trial speed ≤ 30 mm/s; soft limits set to a 50 mm window **5…55 mm next to START** (v0.4.2, D-45 b: every E-stop trial clears HOMED and forces a re-home); both limit switches connected (never stimulate a limit and the E-stop in the same trial) | names, time, PO approval ref (D-06) in the HG log |

| P-3 | Driver PSU off (switch); unplug the NC sense connector at the interface board; fit J-STIM from PB8 through the series resistor to the PA10 input connector; hang the tag "E-STOP SENSE BYPASSED — TEST" on the red button | photo |
